# プロセス全体最適化のための階層的サロゲートモデル構築ロードマップ

## 1. プロジェクトの基本思想（コア・コンセプト）
プロセス全体を単一のAIでブラックボックス化するのではなく、計算負荷が高く非収束エラーの温床となる「蒸留塔」を、精度保証された独立したサロゲートモデル（部品）として構築する。

完成した蒸留塔モジュールを全体最適化（ベイズ最適化：BO）に組み込む**「階層的最適化（Hierarchical Optimization）」**のアプローチをとることで、次元の呪いを回避しつつ、ヒートインテグレーション（熱統合）を含めたプラント全体の大域的最適解を探索する。

---

## 2. 変数設計（モジュールの入出力）
蒸留塔モジュールが、前段プロセスからの変動を受け入れ、かつプラント全体の熱統合を評価できるように設計する。

### 【入力変数：X】（探索・制御の対象）
| 変数名 | 備考 |
| :--- | :--- |
| **塔段数** | ※整数への丸め処理を実装 |
| **フィード段** | 全段数に対する0〜1の相対位置 |
| **還流比** | 分離性能の主要パラメータ |
| **塔頂流量** | または抜出し比 |
| **運転圧力** | 温度と熱負荷に直結 |
| **原料流量** | 前段プロセス（反応器等）との接続用 |

※原料の温度・組成は固定定数として扱う。

### 【出力変数：Y】（HYSYSからの応答）
| 変数名 | 目的 |
| :--- | :--- |
| **塔頂プロパン純度** | 製品仕様の制約条件 |
| **塔底ブタン純度** | またはプロパン回収率 |
| **リボイラー熱負荷** | 加熱エネルギー（OPEX） |
| **コンデンサー熱負荷** | 冷却エネルギー（OPEX） |
| **塔頂温度** | 熱統合（ヒートインテグレーション）の判定用 |
| **塔底温度** | 熱統合の判定用 |

## 3. 実装の4ステップ（ロードマップ）

### ステップ1：初期データ取得（LHSによる空間探索）
- **手法**: Python（`win32com.client`）とHYSYSを連携させ、変数の制約範囲内でラテン超方格サンプリング（LHS）を用いて150パターンの条件を生成・自動入力する。
- **目的**: グリッドサーチによる計算量の爆発を防ぎ、6次元空間全体の大まかな応答曲面を効率的に取得する。非収束データ（計算失敗）は境界線学習用として記録し、有効データ（収束）として60〜80点の確保を目指す。

### ステップ2：デュアル・モデル構築とテスト（収束判定＋性能予測）
ここでは、性質の異なる**2つのモデルを並走**させる。
1. **分類モデル（Feasibility Surrogate）**: HYSYSが「収束するか（True）」「エラーになるか（False）」の境界線を学習する。
2. **回帰モデル（Performance Surrogate）**: 収束したデータに基づき、ガウス過程回帰（GPR）を用いて純度や熱負荷を高精度に予測する。
- **評価**: K分割交差検証（Cross-Validation）を行い、テストデータに対する $R^2$ および RMSE で予測精度を評価する。

### ステップ3：能動学習（Active Learningによる精度向上）
- **手法**: 回帰モデル（GPR）が出力する「予測の不確実性（分散）」および分類モデルの「境界線付近の不確かさ」を利用する。
- **アクション**: モデルが自信を持っていない、または収束・非収束の境界線上にある条件をピンポイントでHYSYSに追加計算させ、2つのモデルを同時に再学習させる。
- **目的**: 最小の計算コストで、空間全域の予測精度と収束判定の正確性を目標値（例: $R^2 > 0.95$）まで引き上げる。

### ステップ4：全体最適化への組み込み（階層的BOの実行）
- **手法**: 完成した「デュアル・サロゲートモデル」を全体最適化アルゴリズムに組み込む。
- **運用**:
	1. 分類モデルが「収束可能」と判定した領域内でのみ探索を行う。
	2. 回帰モデルが高速に性能を予測し、ヒートインテグレーションを含めた全体最適解を特定する。
- **目的**: 収束エラーによる計算の中断を回避しつつ、次元の呪いを克服したプラント全体の最適化を実現する。
